今天的 Agent 转型学习结束。

请不要继续扩展新的学习内容。

基于今天完整的学习过程，对今天进行学习验收和状态更新。

首先结合：

* LEARNING_ROADMAP.md 中今天的目标
* 今天实际讨论的内容
* 我针对代码提出的问题
* 我对知识点的解释和理解情况
* Codex 实际完成的 TASK

判断：

**我真正学会了什么，而不是今天接触了什么。**

## 一、Day XX 学习验收

逐项检查今天原定 Acceptance Criteria。

每项标记：

* 通过
* 部分通过
* 未通过

并简要说明理由。

不要因为代码已经由 Codex 实现就判断我掌握。

重点判断：

我是否能够解释：

* 为什么这么设计
* 调用链怎么运行
* 每一层承担什么职责
* 核心数据如何变化
* 异常情况下发生什么
* 为什么不用其他方案

---

## 二、形成今日学习笔记

生成：

notes/weekXX/dayXX.md

内容保持精炼，包含：

# Day XX — Topic

## Learning Goal

今天原本准备解决什么问题。

## Core Mental Model

用最简单的方式记录今天建立的核心认知。

## Main Call Flow

记录今天最终理解的调用链。

## Key Concepts

只记录真正重要的知识点。

## Why

重点记录：

为什么需要当前设计。

而不只是：

代码怎么写。

## Java Analogy

如果适合，用我熟悉的 Java Backend 概念进行对应。

但不存在合理对应时不要强行类比。

## Common Misunderstandings

记录今天曾经产生或容易产生的错误理解。

## What I Can Explain Now

记录目前已经能够比较完整解释的内容。

## Still Unclear

记录仍然不够清楚的问题。

## Day Conclusion

用 3–5 条总结今天真正获得的能力。

避免把聊天内容全部重新整理一遍。

## 三、生成 LEARNING_STATE 更新内容

根据今天实际掌握情况，给出：

docs/LEARNING_STATE.md

应该更新的完整内容或明确修改项。

重点更新：

* Current Phase
* Current Day
* 已掌握
* 正在学习
* 需要强化
* 当前项目实践
* 未解决问题
* 下一学习目标

已经解决的问题必须从未解决列表删除。

不要无限累积历史状态。

LEARNING_STATE 描述的是：

**我现在是什么状态。**

不是学习流水账。

---

## 四、检查 CAPABILITY_MATRIX

判断今天是否有能力状态变化。

状态只能使用：

* 未学习
* 学习中
* 基本掌握
* 可独立实现

判断标准严格：

### 学习中

接触并基本理解，但仍明显依赖解释。

### 基本掌握

能够：

* 自己解释核心原理
* 阅读相关代码
* 理解调用链
* 在提示下修改或实现

### 可独立实现

能够：

* 独立设计
* 独立编码
* 排查问题
* 解释方案取舍

禁止：

仅仅因为 Codex 帮我实现过，就提升能力等级。

输出今天需要发生变化的能力即可。

没有变化就明确说明：

No capability level changes.

---

## 五、判断是否允许进入下一 Day

最后明确给出：

### Result

PASS / CONDITIONAL PASS / NOT PASS

### Reason

为什么。

### Before Next Day

如果 PASS：

说明明天可以直接进入哪个 Roadmap Topic。

如果 CONDITIONAL PASS：

只列出下一阶段需要顺带强化的问题，不要因为一个非核心细节阻塞整个学习计划。

如果 NOT PASS：

明确指出必须补齐的 1–3 个核心知识点。

不要因为追求“全部懂透”而阻止正常推进。

整个总结遵循：

知识理解 > 代码数量

设计原因 > API记忆

调用链理解 > 框架使用

长期能力 > 当天完成感
